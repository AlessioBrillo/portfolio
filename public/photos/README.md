# Photos — Optimized Site Images

Optimized, ready-to-serve photos live here. **Raw sources never do** — they stay
in a git-ignored directory on the author's machine (see
[`docs/content/photos.md`](../../docs/content/photos.md) for the full pipeline).

## Convention

```
public/photos/
  {subject}-{width}-{hash}.avif   AVIF at each delivery width
  {subject}-{width}-{hash}.webp   WebP at each delivery width
  {subject}-{max}-{hash}.jpg      JPEG fallback (also the `src` of the asset)
```

- `{subject}` is ASCII, lowercase, hyphenated (`vds-volo-01`, `who-portrait`).
- `{width}` is the rendered pixel width, one of `480`, `960`, `1600`.
- `{hash}` is the first 8 hex chars of the raw source's sha-256 (ADR-0016):
  replacing a photo changes every URL, so the immutable cache headers Vercel
  serves for `/photos/*` can never serve stale bytes.
- All files are generated by `npm run images`; never hand-edit them — re-run
  the script and re-paste the printed block into the content module. Use
  `--prune` to remove derivatives from previous runs (including legacy
  unhashed names).
- The asset contract (`npm run photos:check`, CI-enforced) fails on any
  referenced URL that does not exist here, and on any committed derivative
  that no content module references.
